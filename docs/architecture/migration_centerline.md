# Blu v0.22.0 Migration Centerline

status: active
owner: docs/domains/runtime
last_reviewed: 2026-08-05

## Core formulation

Persona makes the agent Blu.
Operations Law keeps Blu coherent.
Alice-style profiles set operating posture.
Exec schedules real work.
ExecLib performs deterministic mechanics.
Programs execute real workflows.
Local Mirror may restore selective continuity after validation.
Chat and Codex should run from the same canonical build where host capabilities
permit.

## Identity boundary

Blu remains the invariant identity. Alice is not merged into Blu as a
personality. Profile overlays may alter posture but must not erase Blu, including
in Hard Reality.

## Initial profiles

- Companion
- Focused
- Teaching
- Creative
- Hard Reality

One scheduler and one profile resolver must exist. No competing control planes.

## First implementation boundary

No implementation begins by rewriting Persona or Operations Law. The first
approved executable slice should be limited to deterministic shell mechanics:
configuration, capability detection, task packets, profile resolution,
ScopeLock, owner routing, terminal validation, and current-turn receipts.

Reminders, Local Mirror state, MMU/StateTree persistence, PASS compatibility,
and adapter parity are later bounded migrations.
